# Page-from-URL reader

- **Headless render IS available server-side** via Replit's `REPLIT_PLAYWRIGHT_CHROMIUM_EXECUTABLE` (a Chromium binary in the nix store). `routes/render.ts` drives it with `playwright-core`: navigate → `networkidle` → inline the computed styles the importer reads (bg/color/font-size/weight/flex-direction/padding/gap) → serialize the live DOM. This is what makes client-rendered SPAs (e.g. Nacho) come back with their hydrated `data-pico-*` instrumentation instead of an empty shell. Falls back to plain `fetch` (delivered shell) when the binary/dep is absent.
  **Why inline styles:** the plugin parses HTML with DOMParser, which does NOT apply CSS — so `readLayout` reads inline `el.style.*` only. The render step must stamp computed styles inline or the importer sees no colors/layout.
  **Gotchas:** `playwright-core` must be in api-server `dependencies` AND in esbuild `external` (build.mjs) or the bundle breaks. Test scripts importing it must run from inside `artifacts/api-server` (module resolution), not `/tmp`.

- **Companion fetch endpoint** `GET /api/render?url=` lives in `artifacts/api-server` (`routes/render.ts`). The plugin UI always routes through it using the build-time baked origin (`__PICO_DEFAULT_ORIGIN__`) — there is NO user-facing "Render service" input anymore (removed as unhelpful). Reason: a plugin iframe hits CORS on most cross-origin sites; a server-side fetch sidesteps that.
  **Why guarded:** an open URL-fetch proxy is an SSRF risk — it rejects private/loopback/link-local/cloud-metadata IPs and re-validates every redirect hop. Keep that guard if you touch the endpoint. **Exception:** public Replit app hosts (`*.replit.app`/`*.replit.dev`/`*.repl.co`) are allowed by hostname even though they resolve to internal cluster IPs in dev — they're the user's own public apps, the main thing this tool recreates.

- **Component resolution is local OR linked library.** `ComponentResolver` in `page.ts` scans local components, then harvests INSTANCE nodes and resolves each `getMainComponentAsync()` to register remote (published-library) main components/sets by name. Library main components are NOT in the document tree unless an instance of them exists. Color variables resolve the same way: local first, then `teamLibrary` import in `figma-helpers.findColorVariable`.

- **Idempotency = full clear, not name-by-name delete.** `generateComponents` wipes every child of the plugin-owned `Pico / Components` page before rebuilding. Name-based deletion left stale duplicates (heading labels shared component names). Headings are also named `"<Name> — label"` so they can't collide.
  **Why:** the page is owned entirely by the plugin, so clearing it is safe and deterministic.

- **Artwork: bytes flow render → UI proxy → code, sizes flow via data-attrs.** Images/SVG can't be drawn from a URL on the figma code side. Pipeline: render step stamps `data-pico-w/h` (rendered box) + makes `<img src>` absolute and stops dropping `<svg>`; UI walk emits image/svg leaves and fetches each `<img>` byte through `GET /api/asset` (separate SSRF-guarded, image-mime-only, 5MB-capped proxy — `/render` only returns HTML), base64s them into a `page.assets` map; code side draws via `figma.createImage`+IMAGE-fill rect (raster) or `figma.createNodeFromSvg` (inline svg or svg-mime img). No `atob`/`TextDecoder` on the code side — use `figma.base64Decode` + a manual UTF-8 decoder.
  **Why the box comes from data-attrs:** DOMParser applies no CSS, so the UI can't compute layout; only the headless render knows the real rendered size.

- **Typography + borders ride the same inline-style channel.** Render step inlines `font-family` for text-bearing nodes and the thickest border side as `data-pico-bw`/`data-pico-bc`. `readLayout` maps font-family (and class fallbacks `font-display`→Platypi etc.) → `layout.fontFamily`, and border → `strokeToken`(tokenFor)/`strokeHex`. `pickTextRole` treats Platypi as display. **Pico display token is 'Platypi'**, so `ensureFonts` must try Platypi ExtraBold/Bold *before* Bricolage/Inter.

- **Page recreation is AUTO-LAYOUT mirroring the HTML, NOT absolute geometry.** The render step stamps `data-pico-flow` (row/col), `-cols` (grid tracks), `-jc`/`-ai` (justify/align), `-pl/-pr/-pt/-pb` (paddings), `-rg/-cg` (row/col gaps), `-x/-y/-w/-h` (rendered box) on every element + `data-pico-doc-w/h` on `<html>`; `/api/render?...&w=<deviceWidth>` sets the Chromium viewport width. `page.ts#buildNode` builds nested auto-layout frames: `layoutMode` from flow (grid → HORIZONTAL+`layoutWrap:"WRAP"` with fixed primary width so items wrap), `itemSpacing` from gap, per-side padding, primary/counter align from jc/ai. **Sizing rule: hug on primary axis, FIXED cross-axis from the box; a child STRETCHes (counter) or `layoutGrow=1` (primary) when its box ≥90% of the parent's inner content size** (`FILL_RATIO`); `align-items:stretch` stretches all children. Text leaves get `textAutoResize:"HEIGHT"` + width from box so they wrap. **Why auto-layout, not the old absolute-ops clone:** `position:fixed` navbars got painted over by the hero in document-order absolute placement (header/logo went missing); doc-order auto-layout stacking fixes z-order naturally and yields editable frames. **NO Pico spacing tokens exist** (only colors/fonts/radius/shadows) — apply captured px spacing values directly. Navbar/header/footer sections (`SECTION_COMPONENTS`) are wrapped via `figma.createComponentFromNode` AFTER the tree is attached to the page (detached nodes can't convert), re-applying `layoutAlign`/`layoutGrow` since conversion resets them. The old `DrawOp`/`buildOps`/`reconstructFromOps`/`composeSamplePage` placeholder path was removed entirely.

- **Download freshness = version sidecar + restart.** The Pico site serves the plugin at a FIXED `public/pico-figma-plugin.zip`, packed only by the pico `dev`/`build` script at workflow startup — so plugin source edits don't reach the download until the `artifacts/pico: web` workflow is restarted. `pack.mjs` also emits `pico-figma-plugin.version.json` (version/builtAt/label/filename) next to the zip; the download page (`figma-plugin.tsx`) fetches it to show the build stamp, set the `download` attr to a versioned filename, and append `?v=<builtAt>` to bust browser cache. `build.mjs#versionInfo()` is the single timestamp source shared by the baked UI label AND the sidecar so they never drift.
  **Why:** users couldn't tell stale from fresh (same fixed name, cached) — the visible stamp + restart are how you confirm "latest".
